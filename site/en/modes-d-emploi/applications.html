All roles

Connect an application

A third-party application works in your organization on your behalf: an automation tool, a dashboard or a calendar. You authorize it from your Relaytour installation, without copying any secret. It receives your rights, never more.

The first sections are for every member and for organization admins. The section “Connect an application to Relaytour” is for the people who write an application.

Starting point

What an application authorization is

An access token suits a program that you install yourself. A third-party application follows another path: it sends you to the consent screen of your installation, and you grant it access.

Your approval creates an application authorization. It belongs to one person and one organization, and it carries a scope, activities and an end date, like an access token. The application never sees your sign-in address or your codes.

Every member

Authorize an application

The application offers a button to connect to Relaytour and asks for the address of your installation. Your browser then opens the consent screen. If you are not signed in, the organizer workspace first asks for your code, then brings you back to this screen.

The organization’s “API” module must be on. Otherwise, the screen says so and no authorization is possible.

The consent screen

/autoriser/<request>

The screen names the application and the host that publishes it. It also shows the address your browser returns to after your answer.

  • OrganizationChoose the organization where the application will work. This choice only appears if you are a member of several organizations.
  • Read onlyLimit the application to reading the tasks, sheets, calendar and team that you see.
  • Read and writeAlso let the application create, edit and comment on tasks on your behalf. This choice only appears if the application asks for writing.
  • Only these activitiesChoose the activities that the application sees. Without this choice, the authorization covers all your activities.
  • AllowGrant access. Your browser returns to the application, which receives its tokens.
  • DeclineGrant nothing. Your browser returns to the application with your refusal.

An application that registered itself carries the “Not verified” label. Its name comes from the application alone, and the installation cannot confirm it.

Your rights, never more

The application reads and edits what you read and edit. It never manages members, creates tokens or changes your account.

An email for each approval

Relaytour sends you an email after each authorization. This email carries a link that revokes the authorization in one step.

One year at most

An authorization lasts one year. Relaytour sends you an email thirty days before it ends. The application must then ask for your approval again.

Every member

Follow and revoke your authorizations

Your authorizations are in your preferences, below your access tokens. The section only appears once you have authorized an application in the organization.

The “Authorized applications” section

/<activity>/preferences#applications

Each line shows the name of the application, its scope, its activities, the date of approval, the end date and the last use.

  • RevokeEnd the authorization. The application receives a refusal on its next request.

A revoked or expired authorization stays in the list for thirty days, with its state. A person has at most twenty active authorizations in one organization.

EventWhat happens to the authorization
You revoke the authorizationIt ends at once.
The application signs outIt ends at once. The application revokes it itself.
An organization admin revokes itIt ends, and Relaytour notifies you by email.
An old token of the application comes backRelaytour treats it as a sign of theft. The authorization ends, and Relaytour notifies you by email.
Your account is archived in the organizationAll your authorizations end.
The “API” module is turned offThe authorization stops answering, then answers again when the module is turned back on.
The “API” module is suspendedAll authorizations in the organization end.
Organization admins

Oversee the organization’s applications

Third-party applications depend on the “API” module. An organization admin turns it on in the “API for third-party programs” panel of the “Organization” screen. The API user guide describes this panel.

Read the authorizations

The panel lists the tokens of the whole organization. An application authorization shows the name of the application and its identifier.

Revoke a member’s authorization

An organization admin revokes a member’s authorization from this list. Relaytour notifies the member by email.

Refuse an application

Under “Refused applications”, an admin enters the identifier of an application. Its authorizations in the organization end, and it can no longer request new ones.

“Lift the refusal” lets the application request authorizations again. The authorizations that the refusal revoked do not come back. An organization refuses at most two hundred applications.

The installation administration can also close the feature, limit it to a list of applications, or refuse an application for all organizations. The reference deployment describes these settings.

People who write an application

Connect an application to Relaytour

Each Relaytour installation is its own OAuth 2.1 authorization server. An application only knows the address of the organizer workspace, and it discovers the rest through the metadata documents.

The flow needs no prior registration and no client secret. The application publishes a document that describes it, and the address of this document serves as its identifier.

AddressWhat it serves
/.well-known/oauth-protected-resourceThe resource metadata (RFC 9728). A 401 refusal from the API points to this document in the WWW-Authenticate header.
/.well-known/oauth-authorization-serverThe authorization server metadata (RFC 8414).
/oauth/autoriserThe start of the flow, opened in the person’s browser.
/oauth/jetonThe exchange of a code, and the renewal of tokens.
/oauth/revocationThe revocation of an authorization by the application (RFC 7009).
/oauth/enregistrementDynamic registration (RFC 7591), only if the installation opens it. It is closed by default.

1. Publish the application’s document

The application publishes a JSON document at a public https address, with a path. This address is its client_id, and the document repeats it.

{
  "client_id": "https://tool.example/relaytour/client.json",
  "client_name": "Example tool",
  "redirect_uris": ["https://tool.example/relaytour/callback"],
  "token_endpoint_auth_method": "none"
}

What the installation checks

  • FetchA public address, with no redirect, within 5 seconds and 16 KB.
  • Name80 characters at most, with no line break.
  • RedirectsTen addresses at most, in https, or in http on 127.0.0.1 or [::1] with any port (RFC 8252).
  • CacheThe installation keeps the document according to its Cache-Control header, for 24 hours at most.

2. Send the person to the consent screen

The application opens /oauth/autoriser in the browser, with a PKCE S256 challenge and the target resource. The resource is the origin of the organizer workspace.

https://your-installation.example/oauth/autoriser
  ?response_type=code
  &client_id=https%3A%2F%2Ftool.example%2Frelaytour%2Fclient.json
  &redirect_uri=https%3A%2F%2Ftool.example%2Frelaytour%2Fcallback
  &scope=lecture%20ecriture
  &state=…
  &code_challenge=…
  &code_challenge_method=S256
  &resource=https%3A%2F%2Fyour-installation.example

The scope is lecture (read), or lecture ecriture (read and write). The person can narrow the requested scope, never widen it. The callback carries code, state and iss (RFC 9207): the application checks that iss is the expected issuer.

3. Exchange the code

The code lasts 60 seconds and works only once. The application exchanges it for an application token and a refresh token.

curl https://your-installation.example/oauth/jeton \
  -d grant_type=authorization_code \
  -d code=… \
  -d code_verifier=… \
  -d client_id=https://tool.example/relaytour/client.json \
  -d redirect_uri=https://tool.example/relaytour/callback \
  -d resource=https://your-installation.example

The response carries access_token (prefix rto_, one hour), refresh_token (prefix rtr_, 90 days) and the granted scope in scope.

4. Call the API

The application token goes in the Authorization header, on /graphql or on /api/v1. The routes, errors and rate limits are those of the API user guide.

5. Refresh

Before the hour ends, the application sends grant_type=refresh_token. It receives a new pair and must forget the old one: an old refresh token that comes back revokes the authorization.

6. Sign out

The application sends one of its tokens to /oauth/revocation. The whole authorization ends, with all its tokens.

OAuth errorWhat it means
invalid_requestA parameter is missing or malformed, for example a missing PKCE challenge or a method other than S256.
invalid_scopeThe requested scope contains a value other than lecture or ecriture.
invalid_targetThe resource parameter is missing or names another installation.
invalid_grantThe code or refresh token is unknown, expired, already used or presented by another application. The authorization may have ended.
access_deniedThe person declined access.

An unknown redirect address, or an unreadable document, does not send the browser back to the application. The installation then shows the error itself, so that it never redirects to an undeclared address.

The consent screen loads nothing from the application, neither a logo nor a script, and it never shows inside a frame.

Good practices

Stay in control

  • Read the screenCheck the host that publishes the application before you allow it. Be wary of a “Not verified” application that you did not expect.
  • The fewest rights possibleChoose read only and only the useful activities, even if the application asks for more.
  • Read your emailsRevoke at once an authorization that you do not recognize, from the link in the email or from your preferences.
  • Clean upRevoke the applications that you no longer use. The date of last use, in the list, helps you spot them.
